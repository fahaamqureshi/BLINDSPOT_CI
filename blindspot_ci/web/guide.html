Guide

How to run BLINDSPOT CI, read what it says, and show it to someone else.

Start in five minutes

You need Python 3.11 or newer. The first run uses scripted answers, so it needs no key and no network.

py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
python -m pytest
python -m blindspot_ci.cli serve

Open http://127.0.0.1:8000. Use Demo for a guided run and Run a test for the full tool. The banner always says which mode you are in.

What each part does

Muse Spark 1.3, the agent
Picks the next test by function calling. It sees earlier results but never the labels.
SAM 3.1, the model under test
Segments the photo from a word such as "fire hydrant" and returns boxes and masks.
Python, the scorer
Compares the best box with the box a person drew. A test passes at IoU 0.35 or higher.
Muse Image 1.0
Makes labeled dark, glare and blur variants. They carry a GENERATED label and are not photos.
Muse Voice Transcribe 1.0
Turns a spoken reviewer note into text.
Muse Wonder 1.0
Writes a plain-language audit of a finished run. It cannot change a score.

Run it live

  1. Put your key in .env as MODEL_API_KEY. Never share or commit that file.
  2. Set BLINDSPOT_PROVIDER=meta and LIVE_API_ENABLED=true.
  3. Choose a dataset in the tool, or run it from the terminal:
$env:BLINDSPOT_PROVIDER="meta"; $env:LIVE_API_ENABLED="true"; $env:BLINDSPOT_DATASET="open"
python -m blindspot_ci.cli experiment --steps 8 --planner muse

A SAM call costs about a quarter of a cent. A full run of 24 photos costs a few cents. A session budget stops the run when the call limit is reached. Real photo sets are built by scripts/fetch_open_data.py, scripts/fetch_open_data_hard.py and scripts/fetch_open_video.py.

Test your own photos

  1. Put 20 to 40 photos of your tray and tag in one folder. Include dark, angled, partly covered and no-tag photos.
  2. Start the labeling tool and draw a box around the tag on each photo. Your name is stored on every label.
  3. Import the labels and run the tests.
python -m blindspot_ci.cli label --folder "C:\path\to\photos" --annotator "Your Name" --out my-labels.json
python -m blindspot_ci.cli import-photos my-labels.json
.\scripts\live_experiment.ps1 -Dataset real -Steps 24

Draw every box yourself. A box copied from SAM or Muse would be the model grading itself. If you can, ask a second person to check some labels and record their name.

Read a result

PASS
The best box overlapped the label by at least the threshold. It is one example.
FAIL_FALSE_NEGATIVE
The object was there and the model found nothing.
FAIL_FALSE_POSITIVE
The object was not there and the model found something.
FAIL_LOCALIZATION
The model found something, but not where the label is.
UNKNOWN and ERROR
Not scored. They never count as a model miss.
Mode label
MOCK_FIXTURE is scripted. LIVE_META is a real SAM call made for this run. CACHE_LIVE_META is a real answer saved earlier and replayed.
95% interval
The range the true pass rate could plausibly sit in. Slices with fewer than 5 scored cases are marked underpowered. Quote counts, not bare percentages.

Release gate

The release gate reads one saved run and says whether that evidence supports moving toward deployment. It makes no model calls and costs nothing. It is conservative on purpose. Open a saved run in the tool to see the Release gate panel under the results table, or run python -m blindspot_ci.cli release-gate --run RUN_ID. The evaluation card carries the same decision.

DEMO_ONLY
The run used mock, fixture, synthetic, generated or corrupted evidence. These can only ever show DEMO_ONLY, however good the numbers look.
NO_GO
A required condition has enough scored cases and its pass rate is below the 0.90 bar. The panel lists the failing conditions and the next experiments to run.
NEEDS_REVIEW
Nothing is clearly failing, but the evidence is thin, uncertain, not reviewed by a second person, or not from a live run.
GO_CANDIDATE
Every check passed. This is not an approval and not a safety certification. A person still decides.

Example: the saved COCO live run gives NO_GO because low light passed 6 of 10 and small object passed 19 of 24. The command exits with 0 for GO_CANDIDATE, 1 for NO_GO, 2 for NEEDS_REVIEW and 3 for DEMO_ONLY.

Record the demo (about three minutes)

Use this order for the hackathon video. Say only what the screen shows.

  1. 0:00 The question. Open the overview. Say what the tool does and that it is not a safety approval.
  2. 0:20 The scoring rule. Drag the amber box in the overview. Show the overlap number and PASS or FAIL change.
  3. 0:45 The free demo. Open Demo and press Run. Point at one passing step and one failing step. Say the banner: scripted answers, not SAM performance.
  4. 1:20 The live run. In the tool, switch to the Open Images set with a live key. Run 6 steps. Show the agent's reason for each choice and the mode label LIVE_META.
  5. 2:00 A real miss. Open a failed case. Show the green model box, the dashed human box and the score.
  6. 2:20 The evidence. Show the results table with intervals, the Release gate panel with its decision and next experiments, the evaluation card download and the Muse Wonder audit.
  7. 2:45 The honest limits. State that the agent has not been shown to beat random order, the photos are hydrants and stop signs, and small slices are underpowered.

What it cannot tell you

  • It tests one prompt wording on one photo per case. A pass is not a guarantee for that condition.
  • Scores use box overlap. There is no mask-quality score, because there are no human masks for the Open Images photos.
  • The public sets show hydrants and stop signs. They do not show how SAM handles your tag.
  • Labels are checked by a second person only when a reviewer is named in the label record.
  • Results hold for the listed model versions and dates.
BLINDSPOT CI is a bounded evaluation, not a safety approval.
